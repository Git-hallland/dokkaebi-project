# 제품 방향과 출시 전 MVP

- 문서 상태: 검토 가능한 초안
- 기준일: 2026-08-28
- 관련 문서: `PROJECT_BRIEF.md`, `AGENTS.md`, `docs/SOURCE_REGISTRY.md`

## 한 문장 정의

`도깨비의세계`를 시작하거나 다시 찾아온 이용자가 최신 공식 근거와 적용 시점을 확인하며 필요한 답을 빠르게 찾는 비공식 지식베이스다.

## 해결할 문제

게임 정보는 공식 홈페이지, 공지, 영상, 보도자료, 커뮤니티 게시물에 흩어진다. 출시 후에는 패치로 정보가 빠르게 낡고, 검색 결과에는 과거 버전의 공략과 출처 없는 주장이 함께 노출될 가능성이 크다.

이 사이트는 다음 질문에 답해야 한다.

- 이 정보는 지금도 맞는가?
- 공식적으로 확인된 내용인가, 편집자의 해석인가?
- 언제 어떤 패치에서 바뀌었는가?
- 관련된 다른 시스템과 항목은 무엇인가?
- 짧은 시간 안에 내가 해야 할 행동만 확인할 수 있는가?

## 대상 사용자

### 1. 출시를 기다리는 예비 이용자

- 알고 싶은 것: 출시일, 사전예약, 지원 플랫폼, 세계관, 공개된 특징
- 필요한 경험: 공식 발표만 압축한 최신 요약과 원문 링크
- 출시 전 최우선 사용자다.

### 2. 처음 시작한 이용자

- 알고 싶은 것: 초반 진행, 성장 방향, 스킬 선택, 놓치기 쉬운 보상
- 필요한 경험: 짧고 순서가 분명한 가이드, 관련 항목 바로가기
- 출시 직후 최우선 사용자로 전환된다.

### 3. 특정 답을 찾는 플레이어

- 알고 싶은 것: 아이템 획득처, 보스 조건, NPC 위치, 제작 재료, 패치 변경점
- 필요한 경험: 빠른 검색, 구조화된 필터, 버전과 검증일 표시
- 데이터가 확보되는 출시 후부터 핵심 검색 사용자다.

### 4. 정보를 작성·검수하는 운영자

- 하고 싶은 것: 출처를 남기고 빠르게 작성하며 변경분만 검수·공개
- 필요한 경험: 초안과 공개본 분리, 출처 연결, 미리보기, 변경 이력, 만료 알림
- 사이트 품질을 결정하므로 공개 화면과 동등한 핵심 사용자다.

## 차별점

### 출처가 콘텐츠의 부속물이 아니라 데이터다

각 핵심 주장에 출처와 확인일을 연결한다. 페이지 하단에 링크 몇 개를 나열하는 수준을 넘어, 무엇을 뒷받침하는 출처인지 추적할 수 있게 한다.

향후 콘텐츠 타입과 데이터 모델 설계 단계에서는 `content → claim → claim_source → source`처럼 페이지 전체가 아니라 특정 핵심 주장과 근거를 연결하는 구조를 후보로 검토한다. 이는 개념적 후보일 뿐이며, 현재 DB 스키마나 `claim` 테이블의 구현을 확정하지 않는다.

### 최신값과 변경 이력을 함께 제공한다

사용자에게는 최신 결론을 먼저 보여주고, 과거 값과 변경 근거는 접어서 확인할 수 있게 한다. 오래된 공략을 삭제만 하지 않고 적용 버전과 폐기 시점을 기록한다.

### 검색 결과에서 답을 먼저 준다

장문의 서론이나 광고보다 핵심 답, 적용 버전, 확인일을 먼저 배치한다. 항목 페이지는 표와 짧은 절차를 우선하고 상세 설명은 그다음에 둔다.

### 출시 전에는 작고 신뢰할 수 있게 시작한다

내용 없는 문서 수를 늘리지 않는다. 공식 정보가 있는 소수의 완성된 문서와 운영 품질로 검증한다.

## 하지 않을 것

- 공식 커뮤니티의 공지와 기사를 그대로 복제하는 뉴스 미러
- 출처 없는 루머·유출·추측 콘텐츠
- 정보가 없는 카테고리 페이지의 대량 공개 및 색인
- 허가되지 않은 이미지·데이터의 대량 수집과 재배포
- 출시 전부터 모든 직업·아이템·몬스터 문서를 만들어 둔 것처럼 보이는 위키
- 자체 게시판, 채팅, 길드 모집 등 커뮤니티 기능
- 계정 거래, 대리, 현금 거래와 연결되는 기능
- 반복 시간표 앱 기능

## 출시 전 MVP 목표

9월 쇼케이스와 10월 출시 때 공식 정보를 당일 등록하고 검수해 공개할 수 있으며, 방문자는 모바일에서 최신 공식 사실과 근거를 빠르게 찾을 수 있어야 한다.

### 공개 화면

1. 홈
   - 최신 확인 정보 3~5개
   - 출시·쇼케이스 상태
   - 최신 공식 소식
   - 주요 가이드 진입점
   - 비공식 팬 사이트 고지
2. 문서 상세
   - 제목, 한줄 답변, 본문
   - 상태와 마지막 검증일
   - 근거 출처
   - 관련 문서
   - 잘못된 정보 신고
3. 공식 소식 목록 및 상세 요약
   - 원문을 복제하지 않은 요약
   - 게시일, 확인일, 원문 링크
4. 통합 검색
   - 제목, 요약, 본문 검색
   - 공개 콘텐츠만 노출
5. 기본 정보 페이지
   - 사이트 소개 및 비공식 고지
   - 출처·편집 원칙
   - 개인정보 처리 안내
   - 문의 또는 오류 신고 안내

### 관리자 기능

1. 콘텐츠 생성·수정·미리보기
2. `draft → review → published → archived` 상태 전환
3. 출처 등록과 콘텐츠 연결
4. 마지막 확인일과 재검수 예정일 관리
5. 변경 내용 비교와 이력
6. 잘못된 정보 신고 목록과 처리 상태
7. 고정 slug와 리디렉션 관리
8. 공개·비공개 상태가 반영된 검색 및 sitemap

### 초기 콘텐츠 8개

공식 정보가 충분한 범위에서 다음 문서를 우선 제작한다.

1. `도깨비의세계`는 어떤 게임인가
2. 출시일과 현재 일정
3. 사전예약 방법과 공식 보상
4. 지원 플랫폼과 플레이 환경: 확인된 범위만 작성
5. 원작 `멸귀수도전`과 게임의 관계
6. 순리·역리와 세 세계: 공개된 세계관
7. 자유 성장과 스킬 덱 빌딩: 공개 정보 요약
8. 자주 묻는 질문

9월 쇼케이스 후에는 기존 문서를 갱신하고, 새 공식 정보가 충분할 때만 별도 문서를 추가한다.

## MVP에서 제외하는 기능

- 사용자 회원가입과 일반 사용자 편집
- 댓글, 게시판, 실시간 채팅
- 개인 캐릭터·빌드 저장
- 딜 계산기와 시뮬레이터
- 다국어
- 네이티브 앱
- 푸시 알림
- 자동 크롤링과 자동 공개
- 광고 네트워크 연동
- 상세 아이템·몬스터·NPC 데이터베이스의 공개

데이터 모델은 향후 확장을 막지 않게 설계하되, 공개 기능은 검증된 데이터가 생길 때 추가한다.

## 핵심 사용자 흐름

### 방문자

검색 또는 홈 진입 → 핵심 답 확인 → 적용 시점·출처 확인 → 관련 문서 이동 → 오류 발견 시 신고

### 편집자

출처 등록 → 초안 작성 → 주장과 출처 연결 → 검수 요청 → 검수자가 변경·권리·표현 확인 → 공개 → 재검수일에 최신성 확인

### 일정 변경

새 공식 발표 등록 → 이전 출처와 대체 관계 연결 → 영향받는 문서 검색 → 최신 결론 수정 → 변경 이력 공개 → 필요 시 sitemap 갱신

## 정보 구조

출시 전 상단 탐색은 작게 유지한다.

- 홈
- 게임 소개
- 가이드
- 공식 소식
- 검색

직업·스킬, 아이템·장비, 몬스터·보스, 지역·NPC, 던전·콘텐츠, 제작·생활, 이벤트·쿠폰, 패치노트는 정보가 생겼을 때 단계적으로 독립 메뉴로 승격한다. 공개 문서가 없는 메뉴는 노출하지 않는다.

## 성공 기준

출시 전 MVP의 성공은 페이지 수나 방문자 수만으로 판단하지 않는다.

- 초기 콘텐츠 8개 모두 핵심 주장에 공식 출처가 연결돼 있다.
- 공개 콘텐츠 100%에 마지막 확인일이 표시된다.
- 초안과 검수 중 콘텐츠가 공개 검색·sitemap에 노출되지 않는다.
- 모바일에서 사용자가 출시 일정과 사전예약 답을 30초 안에 찾을 수 있다.
- 쇼케이스 발표 후 24시간 안에 관련 문서를 검수·갱신할 수 있다.
- 신고가 어느 콘텐츠와 관련됐는지 추적되고 처리 상태가 남는다.
- 빈 문서와 출처 없는 사실의 공개 건수는 0이다.

트래픽과 검색 순위는 관찰하되, 출시 전에는 정보 품질과 운영 속도를 우선 지표로 삼는다.

## 출시 후 확장 판단

다음 근거가 생길 때 기능을 확장한다.

- 실제 검색어와 사이트 내 검색 실패어
- 오류 신고와 반복 문의
- 공식 패치 주기와 콘텐츠 변경량
- 편집자가 정보를 갱신하는 데 걸리는 시간
- 검색 유입 후 이탈률과 관련 문서 이동

사용자가 많이 찾고 공식 또는 직접 검증 가능한 데이터가 있는 영역부터 상세 데이터베이스로 확장한다. 광고는 반복 방문과 검색 유입이 확인된 뒤, 가독성과 성능을 해치지 않는 범위에서 별도 결정한다.

## 아직 결정할 사항

- 사이트 이름과 도메인
- 운영 인원과 검수 권한 모델
- 신고 접수 시 수집할 개인정보 범위
- 초기 콘텐츠의 문체와 표준 템플릿
- 기술 스택, CMS 방식, 데이터베이스, 검색 엔진
- 배포 지역, 예상 비용, 백업과 장애 대응 수준
- 권리자의 팬 콘텐츠·이미지 사용 정책 확인 결과
